# 随包样本

本目录的向量、图和预期结果由本项目合成，按 CC0 1.0 提供。一个 32×128 的查询，四个文档，真实长度分别为 1、2、3、129，共 135 个 token。10 个粗码本条目中四个有入口，六个为空；细码本有 35 行。三个阶段分别需要处理不满 8、32、128 行的尾块。两个文档同分，按文档 ID 升序决胜。

| 文件 | 作用 |
|---|---|
| `queries.npy`、`query_ids.json` | 查询向量与逻辑顺序 |
| `coarse.npy`、`fine.npy` | 粗、细码本 |
| `raw.npy`、`codes.npy` | 连续 FP16 原始文档向量与细码 |
| `token-offsets.u64`、`membership-offsets.u64`、`memberships.u32` | 文档 token 区间、成员区间、成员 ID |
| `entries.u32`、`degree.u32`、`adjacency.u32` | 各簇入口、节点出度和定宽邻接数据 |
| `runner.json`、`files.json` | 维数、分片、相对文件名；逐文件字节数与 SHA-256 |
| `expected.json` | 独立计算的精确候选 ID 和有序定点结果 |

`prepare` 导入提供的有向图，用原始输入生成源索引快照、文档 Merkle 树、行与块承诺、认证清单和 16 个发布包。样本使用可复现测试密钥；源快照所有者的 32 字节种子每个字节为 17。阶段清单沿用实测实验的另一个身份，其 32 字节种子的每个字节为 19。样本密钥和签名仅供测试。TLS 私钥和令牌由每次运行独立产生。

期望候选按 ID 为 `[0, 1, 2, 3]`，有序结果为 `[(1, 25768755200), (2, 25768755200), (0, 27915976712)]`。检索固定点和尾部补零语义由 release 客户端独立核验。生成的认证材料位于 `artifacts/sample/`。比较两次从头准备时，固定输入和准备程序二进制身份；源清单的 provenance 同时绑定这两项。跨路径重新编译可能改变准备程序摘要，此时比较数据根、材料行序、阶段矩阵、搜索轨迹与排名，并验各自签名。
